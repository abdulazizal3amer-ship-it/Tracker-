# Tracker — نظام متابعة المشاريع والمهام

نظام ويب بسيط لإدارة المشاريع والمهام لفريق صغير (نحو 10 أشخاص)، بالعربية والإنجليزية، **بلا أي خادم تديره**:

- **الواجهة** على GitHub Pages (مجاناً).
- **قاعدة البيانات والحسابات** على Supabase (الخطة المجانية).
- **النشر تلقائي** عبر GitHub Actions عند كل تعديل.

وثيقة متطلبات الأعمال الكاملة: [`docs/BRD.md`](docs/BRD.md)

## ما يفعله النظام (الإصدار 1.0)

| الوحدة | الوظائف |
| --- | --- |
| الحسابات | دخول بالبريد وكلمة المرور، كلمة مرور مؤقتة تُغيَّر عند أول دخول، استعادة كلمة المرور، ثلاثة أدوار: مدير النظام، مدير مشروع، عضو فريق |
| المشاريع | إنشاء وتعديل، أعضاء، حالة (نشط/متوقف/مكتمل/مؤرشف)، نسبة إنجاز تلقائية |
| المهام | إسناد **لعضو واحد أو لمجموعة أعضاء**، أولوية، تاريخ استحقاق، أربع حالات |
| العرض | لوحة كانبان بالسحب والإفلات، عرض قائمة مع تصفية وبحث، صفحة "مهامي" |
| التعاون | تعليقات مع إشارة `@الاسم`، سجل نشاط لكل مهمة |
| الإشعارات | فورية داخل التطبيق: إسناد، تغيير حالة، تعليق، إشارة |
| المتابعة | لوحة رئيسية: المتأخر، المستحق هذا الأسبوع، إنجاز كل مشروع، حمل العمل لكل عضو |

### الصلاحيات (مطبقة داخل قاعدة البيانات نفسها)

| العملية | مدير النظام | مدير مشروع | عضو |
| --- | :-: | :-: | :-: |
| إدارة المستخدمين | ✓ | – | – |
| إنشاء مشروع | ✓ | ✓ | – |
| إسناد مهمة لأي عضو في المشروع | ✓ | ✓ (مشاريعه) | لنفسه فقط |
| تغيير حالة مهمة | ✓ | ✓ | إن كان من المسندين إليهم |
| حذف مهمة | ✓ | ✓ (مشاريعه) | – |

## خطوات التشغيل (مرة واحدة، نحو 30 دقيقة)

### 1) إنشاء قاعدة البيانات على Supabase

1. أنشئ حساباً في [supabase.com](https://supabase.com) ثم **New project** (اختر منطقة قريبة مثل Frankfurt، واحفظ كلمة مرور قاعدة البيانات).
2. افتح **SQL Editor** وشغّل الملفات التالية **بالترتيب**، كل ملف على حدة (انسخ المحتوى والصقه ثم **Run**):
   1. [`supabase/migrations/001_tables.sql`](supabase/migrations/001_tables.sql)
   2. [`supabase/migrations/002_functions.sql`](supabase/migrations/002_functions.sql)
   3. [`supabase/migrations/003_rls.sql`](supabase/migrations/003_rls.sql)

### 2) إعدادات الدخول (مهم للأمان)

من **Authentication**:

- **Sign In / Providers**: أوقف **Allow new users to sign up**، فالمدير وحده ينشئ الحسابات.
- **URL Configuration**: ضع رابط موقعك على GitHub Pages (من الخطوة 5) في **Site URL** وفي **Redirect URLs**، حتى تعمل روابط استعادة كلمة المرور.

> رسائل البريد المدمجة في Supabase محدودة جداً. لكي تصل رسائل استعادة كلمة المرور لكل الموظفين، اضبط بريداً خاصاً من **Authentication > Emails > SMTP Settings** (مثل Gmail أو Resend).

### 3) حساب مدير النظام الأول

1. **Authentication > Users > Add user > Create new user**: بريدك وكلمة مرور، وفعّل **Auto Confirm User**.
2. افتح [`supabase/seed.sql`](supabase/seed.sql)، وغيّر البريد والاسم فيه، ثم شغّله في **SQL Editor**.

### 4) دالة إنشاء المستخدمين

هذه الدالة تتيح للمدير إنشاء الحسابات من داخل التطبيق، وتُبقي المفتاح السري خارج المتصفح.

1. **Edge Functions > Deploy a new function > Via Editor**.
2. الاسم: `create-user` (بالضبط).
3. الصق محتوى [`supabase/functions/create-user/index.ts`](supabase/functions/create-user/index.ts) ثم **Deploy**.

(أو عبر سطر الأوامر: `npx supabase functions deploy create-user --project-ref <المعرف>`)

### 5) النشر على GitHub Pages

1. من Supabase: **Project Settings > API Keys** وانسخ:
   - **Project URL** (من Project Settings > Data API)
   - المفتاح العام **anon / publishable** (وليس service_role أبداً)
2. في هذا المستودع على GitHub: **Settings > Secrets and variables > Actions > New repository secret** وأضف:

   | الاسم | القيمة |
   | --- | --- |
   | `SUPABASE_URL` | Project URL |
   | `SUPABASE_ANON_KEY` | المفتاح العام |

3. **Settings > Pages > Build and deployment > Source**: اختر **GitHub Actions**.
4. **Actions > Deploy to GitHub Pages > Run workflow**.
5. بعد دقيقتين يظهر رابط الموقع في **Settings > Pages**، ويكون عادة بالشكل:
   `https://abdulazizal3amer-ship-it.github.io/Tracker-/`
   ضعه في إعدادات Supabase (الخطوة 2).

### 6) الاستخدام

1. ادخل بحساب المدير، ثم **المستخدمون > مستخدم جديد** لإضافة مدراء المشاريع والأعضاء. يولّد النظام كلمة مرور مؤقتة؛ أرسلها للموظف، وسيُطلب منه تغييرها عند أول دخول.
2. ينشئ مدير المشروع مشروعه ويضيف أعضاءه، ثم يُنشئ المهام ويسندها لعضو أو أكثر.

## النسخ الاحتياطي والبقاء نشطاً (اختياري ومستحسن)

مشروع Supabase المجاني **يتوقف بعد أسبوع بلا استخدام** (مثلاً في الإجازات)، والبيانات لا تُحذف لكن الموقع يتوقف حتى تعيد تفعيله من لوحة Supabase.

| التشغيل التلقائي | ما يفعله | الأسرار المطلوبة |
| --- | --- | --- |
| `keepalive.yml` | طلب خفيف كل 3 أيام ليبقى المشروع نشطاً | تعمل بالسرّين السابقين |
| `backup.yml` | نسخة أسبوعية مشفرة من قاعدة البيانات، تُحفظ 90 يوماً في صفحة التشغيل | `SUPABASE_DB_URL` (رابط **Session pooler** من زر **Connect** في Supabase) و `BACKUP_PASSPHRASE` (كلمة سر تختارها وتحفظها) |

فك تشفير نسخة: `gpg --decrypt backup.sql.gz.gpg | gunzip > backup.sql`

## للمطورين

```bash
npm install
cp .env.example .env    # ضع رابط Supabase والمفتاح العام
npm run dev             # تشغيل محلي
npm test                # اختبارات منطق الأعمال
npm run test:db         # اختبار الجداول والصلاحيات على PostgreSQL حقيقي (بلا خادم)
npm run build
```

### الأمان باختصار

- الحماية الحقيقية في **سياسات RLS** داخل PostgreSQL: حتى لو عدّل أحد كود الواجهة، لا يرى ولا يعدّل إلا ما تسمح به صلاحيته.
- المفتاح العام في الواجهة آمن بوجود RLS. مفتاح `service_role` لا يوضع أبداً في المستودع؛ يعيش فقط داخل دالة Supabase.
- كلمات المرور تديرها Supabase Auth مشفرة، ولا تُخزَّن في جداولنا.
- الحساب الذي لم ينشئه المدير يبدأ معطّلاً، حتى لو نُسي إيقاف التسجيل العام.
